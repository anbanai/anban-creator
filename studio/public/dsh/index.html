Install Anban Creator for DeepSeek Harness

This page is written for DeepSeek Harness (DSH). Complete the installation on the user's machine.

Safety

  • Never print, log, commit, or upload the user's ANBAN_API_KEY.
  • Ask the user for the key only when credentials are needed.
  • Presets are global under the resolved DSH home and shared by every profile using it. Check which other profiles depend on them before any destructive command.
  • Never delete a Preset or lock directory recursively. Back up a locally modified owned Preset first.

Scope

Installation is two explicit steps with two scopes. The Bundle is profile-local. Presets are global at $DSH_HOME/.agent-presets. Bundle activation never installs, upgrades, or removes Presets, so always run the explicit Preset command after installing, upgrading, or rolling back the Bundle. Presets currently exist for Article and Seednote only.

Prerequisites

DeepSeek Harness with the dsh CLI, and Node >=22.19.0 <23 or >=24.0.0.

Normalize the DSH home before any filesystem operation. Expand an exact ~, ~/, or ~\ form, fall back to ~/.dsh when DSH_HOME is unset, empty, or whitespace-only, otherwise preserve the configured value, and resolve the result to an absolute path. Refuse an empty result or a filesystem root.

NORMALIZED_DSH_HOME="$(
node <<'NODE'
const os = require('node:os')
const path = require('node:path')

const configured = process.env.DSH_HOME ?? ''
let value = configured
if (configured.trim() === '') value = path.join(os.homedir(), '.dsh')
else if (configured === '~') value = os.homedir()
else if (configured.startsWith('~/') || configured.startsWith('~\\')) {
  value = path.join(os.homedir(), configured.slice(2))
}

const normalized = path.resolve(value)
if (normalized === path.parse(normalized).root) {
  console.error('Refusing to use the filesystem root as DSH_HOME')
  process.exit(1)
}
process.stdout.write(normalized)
NODE
)" || {
  printf '%s\n' 'Unable to normalize DSH_HOME' >&2
  exit 1
}
[ -n "$NORMALIZED_DSH_HOME" ] || {
  printf '%s\n' 'Refusing an empty normalized DSH_HOME' >&2
  exit 1
}
export DSH_HOME="$NORMALIZED_DSH_HOME"
unset NORMALIZED_DSH_HOME
install -d -m 700 "$DSH_HOME"
chmod 700 "$DSH_HOME"

Get the API key

Ask the user to sign in at https://creator.anbanai.com/settings#api-key-settings, create a platform key, and keep the full value. The full key is displayed only once.

Select the active profile

Choose the target profile once and use it for every command below. Use web for public DeepSeek Harness Web.

ACTIVE_PROFILE="web"

Install

Install only a published, immutable artifact. Resolve one exact version from the public registry, then pin it exactly. Never install an unversioned package, a dist-tag, or a version range.

  1. Resolve the current published version of the Anban DSH plugin and confirm it resolves anonymously from npm.
  2. Add that exact version to the selected profile.
  3. Compose the profile configuration with --dump-config to prepare the peer fallback before the first standalone Bundle command.
  4. Materialize the global Presets with the explicit Preset command.
PUBLISHED_VERSION="$(npm view "@anban/dsh-plugin" version)"
dsh plugin --profile "$ACTIVE_PROFILE" add "@anban/dsh-plugin@${PUBLISHED_VERSION}"
dsh --profile "$ACTIVE_PROFILE" --dump-config
dsh plugin --profile "$ACTIVE_PROFILE" exec anban-dsh install-presets

Bundle activation alone leaves Presets unchanged. If Preset installation fails after a successful Bundle install, keep the Bundle, resolve the reported error, and rerun install-presets.

Credential configuration

The Creator MCP endpoint is fixed at https://creator.anbanai.com/mcp and is not a profile option. The official DSH credential precedence is inherited process environment (read-only, highest priority), then $DSH_HOME/.credentials.yaml (managed, writable), then invocation-project .env, then $DSH_HOME/.env. For persistent Web use, write the key into the managed document without echoing it.

ANBAN_API_KEY: <user-provided-key>

On POSIX keep that file at mode 0600. Do not put the key or a serialized Authorization header in a Preset, a command argument, a log, a screenshot, a test fixture, or a generated artifact. DeepSeek Harness model onboarding configures model-provider credentials, not third-party credentials like this one.

chmod 600 "$DSH_HOME/.credentials.yaml"

Verify

  1. Run the read-only status command and confirm the installed Presets report state=current. The states are absent, current, outdated, modified, and unowned.
  2. Restart DeepSeek Harness if the credential was only added to the environment.
  3. Confirm the Creator MCP connection can list Anban projects.
dsh plugin --profile "$ACTIVE_PROFILE" exec anban-dsh status

Inside an interactive session the equivalent registered commands are /anban-presets-install, /anban-presets-status, /anban-presets-install force, and /anban-presets-remove confirm. Both surfaces call the same Preset manager.

Shell and interactive commands

dsh plugin --profile "$ACTIVE_PROFILE" exec anban-dsh install-presets
dsh plugin --profile "$ACTIVE_PROFILE" exec anban-dsh status
dsh plugin --profile "$ACTIVE_PROFILE" exec anban-dsh install-presets --force
dsh plugin --profile "$ACTIVE_PROFILE" exec anban-dsh remove-presets

Advanced artifacts

Prefer the public npm package. When a registry install is not possible, use one of these verified artifacts instead of an unpinned install.

  • Checksummed release tarball: download anban-dsh-plugin-X.Y.Z.tgz and the matching .sha256 from the matching anbanai/anban-creator release tag, verify the digest, then add that exact archive.
  • Immutable Git source: add the approved https://github.com/anbanai/creator-harness.git repository pinned to a full 40-character commit or a protected release tag, never a branch or floating URL, then approve the prepare build in the same profile and repeat the exact add command.
  • Local development: run pnpm pack --json in the plugin repository and add the exact tarball path reported in the filename field. Never install a source directory with a file: specifier.

Upgrade, rollback, and removal

Upgrade the profile-local Bundle first, compose the profile configuration, then explicitly reconcile the global Presets and check status again. Before --force or removal, check status and back up local changes.

dsh plugin --profile "$ACTIVE_PROFILE" exec anban-dsh status
PUBLISHED_VERSION="$(npm view "@anban/dsh-plugin" version)"
dsh plugin --profile "$ACTIVE_PROFILE" add "@anban/dsh-plugin@${PUBLISHED_VERSION}"
dsh --profile "$ACTIVE_PROFILE" --dump-config
dsh plugin --profile "$ACTIVE_PROFILE" exec anban-dsh install-presets
dsh plugin --profile "$ACTIVE_PROFILE" exec anban-dsh status

A normal upgrade replaces outdated owned Presets and refuses modified and unowned state. --force is destructive and is only for intentional replacement. Rollback installs an exact previously published Bundle version and then reconciles Presets with --force because newer owned Presets can look modified to an older package. Removal takes the global Presets away first, then the profile-local Bundle.

dsh plugin --profile "$ACTIVE_PROFILE" exec anban-dsh status
dsh plugin --profile "$ACTIVE_PROFILE" exec anban-dsh remove-presets
dsh plugin --profile "$ACTIVE_PROFILE" remove @anban/dsh-plugin

Troubleshooting

The CLI prints stable, secret-safe operational codes:

  • ERR_RUNTIME_MISSING: an incomplete package or source install lacks dsh/lib/cli.js. Remove only that profile dependency, install the exact verified npm version or packed .tgz, compose the profile configuration, and rerun Preset installation.
  • ERR_PRESET_UNOWNED: the target directory has no Anban ownership record. Removal is refused and replacement needs an explicit trust decision.
  • ERR_PRESET_MODIFIED: back the Preset up, then use --force only when replacement is intended.
  • ERR_PRESET_LOCKED: another mutation is active. Wait and rerun status; do not disturb the lock.
  • ERR_PRESET_LOCK_INVALID: stop DSH writers sharing this home, back up $DSH_HOME/.agent-presets, inspect .anban-dsh.lock/owner.json, and move the lock residue to a unique quarantine path instead of deleting it.
  • ERR_PRESET_ROLLBACK and ERR_PRESET_OPERATION: preserve the reported recovery path, check filesystem access and space, and retry the same explicit step.

Runtime limitation

The MCP connection can be healthy while task-context operations still fail. Operations that require an Anban task or execution context need a valid current task and execution. Without that context, report the failure and continue only with capabilities that do not require it.

Result

Report the installed plugin version, the selected profile, the Preset states reported by status, whether setup verification passed, and any action still required from the user. Do not include the API key.
