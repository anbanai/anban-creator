# 小红书内容图生成规范

## 三段式结构：中间页与尾部页的分工

封面之后的图片分为两类，各自服务不同的用户行为阶段：

| 阶段 | 用户状态 | 设计目标 | 核心指标 |
|------|----------|----------|----------|
| 封面 | 信息流扫视，0.5 秒决策 | 让用户点进来 | 点击率 |
| **中间页 `[内容]`** | 已点进来，决定是否看完 | 让用户看完 | 完读率（直接影响推流） |
| **尾部页 `[尾部]`** | 看完了，决定是否互动 | 让用户互动/关注 | 点赞/收藏/关注率 |

### 中间页 `[内容]` 的设计逻辑

**核心目标是完读率**。完读率直接影响平台推流权重，因此中间页的所有设计都应降低用户的"看完成本"：

- **每页只讲一个信息点**：用户没有耐心一次处理多个概念，3 秒能看懂是基准要求
- **视觉引导代替阅读**：用箭头、框选、编号、高亮等视觉元素让信息"被看到"而非"被读到"，降低认知负荷
- **步骤化/结构化优先**：人脑更容易处理有序信息（1/2/3），比散文式排列留存率更高
- **风格连贯性**：与封面视觉语言保持一致，给用户连续的阅读体验，不能"换台"的感觉

### 尾部页 `[尾部]` 的设计逻辑

**核心目标是转化**。用户看完内容后处于"满足感最高点"，是促成互动的最佳时机，也是最脆弱的一刻——一旦引入新信息，价值感会被稀释：

- **不引入新内容**：尾部不是内容页，避免冲淡已建立的价值感
- **提炼记忆点**：用一句话总结全文核心，强化用户"我学到东西了"的感受
- **降低互动门槛**：提问比直接请求更容易引发评论（"你踩过这个坑吗？"比"请评论"有效 10 倍）
- **给出关注理由**：引导关注时要告诉用户"关注了还能获得什么"，而不是空洞的"关注我"
- **排版克制收敛**：视觉上要"收"不要"放"，尾部是收尾而非高潮

## 合规要求

- **不要带有任何小红书的 logo**
- **不要有右下角的用户 ID 以及 logo**
- 参考图片中的水印和 logo（尤其是右下角、左上角）必须去掉
- 不要有手机边框或白色留边
- 风格必须严格参考封面，保持统一

## 设计规范

### 1. 整体风格

- **延续封面笔记感**：每页都像一张独立的知识笔记，不是PPT幻灯片，不是科普海报
- **一图流知识卡片**：每页只有一个核心信息点，像在便利贴上写了一句话精华
- **朋友分享语气**：用类比代替术语，"就像..."比"即..."有温度，非专家教导
- 与封面严格统一，使用相同 `$STYLE` 参数

### 2. 内容密度要求（关键）

- **文字占比**：≤30%（大幅压缩，密集文字会造成"科普海报感"）
- **留白**：≥50%，留白是设计呼吸感的核心，不是设计失误
- **每页一个信息点**：用户3秒能看懂这一页在讲什么，不贪多
- **不追求信息丰富度**：内容图不是信息图，不需要3个信息层级，一层够了
- **标注代替文字**：用手绘箭头、圆圈、荧光划线传递重点，减少正文文字量

### 3. 文字排版

- **字体**：圆润友好（圆体/手写体/圆润无衬线体），禁止粗黑体
- **高亮**：关键词用色块填充或荧光笔划线（粉/黄/绿），而非粗体加深
- **松散有呼吸**：行间距宽松，字间距适中，不要密集堆砌
- 所有文字内容必须完整呈现

### 4. 视觉元素

- **实拍质感背景**：每页背景与封面保持风格一致，细节丰富，具体场景与内容主题匹配，避免相同背景重复
- **手绘标注**：手绘箭头、铅笔圆圈、荧光笔划线、贴纸感标签，增加手工标注感
- **配色与封面统一**：延续封面确定的色调和氛围，低饱和温润
- **每页构图各异**：主体位置、留白方向、背景场景均不相同，禁止重复视觉元素

### 5. 视觉多样性要求（防止审美疲劳）

- **背景场景轮换**：3张内容图至少用3种不同背景场景，具体场景根据内容主题选择，保持多样性
- **构图角度变化**：上中下/左右/斜对角等多种构图，禁止每页相同
- **主体位置轮换**：文字/焦点物在画面中的位置每页不同（左上/居中/右下等）
- **标注风格多样**：手绘箭头/荧光划线/圆圈标注/贴纸标签，每页搭配不同
- 整体风格统一（色系/调性），但每页视觉构成必须有新意

### 6. 禁止清单

- ❌ 3D 渲染物体（廉价感，与笔记调性不符）
- ❌ 纯色/纯渐变背景（无质感，像PPT幻灯片）
- ❌ 粗黑体/厚重字体（严肃感，失去笔记温度）
- ❌ 对称PPT布局（规整感，不像真人手写笔记）
- ❌ 科普海报风格（白底+图表+密集文字+学术排版）
- ❌ 密集文字排版（超过30%画面面积）
- ❌ 重复视觉元素（多张图相同背景/构图/标注方式）
- ❌ 手机边框或白色留边

## 页面类型要求

### [内容] 类型

- 每页聚焦单一信息点，朋友语气讲解（用类比、口语，不用术语）
- 手绘标注引导视线，用箭头/圆圈/荧光划线代替密集正文
- 关键词色块高亮或荧光划线，而非粗体/下划线

### [尾部] 类型

- 不引入新内容，视觉上"收"而非"放"，维持笔记感到最后
- 一句话提炼全文核心记忆点
- 互动引导用提问而非命令（降低门槛）
- 关注引导说明关注后能获得什么（给出理由）
- 可有完成感标志，但不宜夸张

---

## 技术规格

- **比例**：竖版 3:4（小红书标准比例）
- **画质**：高清，适合手机屏幕查看
- 所有文字内容必须完整呈现
- 符合正确的竖屏观看排版，不能左右旋转或倒置
- 直接输出图片，无手机边框或白色留边

---

## 风格一致性

- 必须与封面图保持统一：非封面图统一用 `--ref ./cover.png` 参考封面
- 封面确定了整体色调和设计风格，后续图片通过参考图延续风格
- 严禁与封面风格割裂

## CLI 命令

```bash
# 计算内容图总数（封面之外所有页数）
COUNT=<内容图总张数>

# 【必须使用组图模式】一次生成所有内容图，同时参考封面保持风格一致
# --count 指定张数；--ref 指定封面图路径
# 输出到目录，自动命名 image_01.png ... image_0N.png
# 禁止逐张调用 image generate
anbanwriter image generate "{unified_content_description}" \
  --count $COUNT \
  --mode xhs --ref ./cover.png -o ./content_images/

# 逐张上传到微信素材库
anbanwriter image upload ./content_images/image_01.png
anbanwriter image upload ./content_images/image_02.png
# ... 依次上传
```

> **注意**：封面图单独生成（`image generate ... -o ./cover.png`），内容图使用组图模式，同时通过 `--ref ./cover.png` 保持与封面的风格一致性。
