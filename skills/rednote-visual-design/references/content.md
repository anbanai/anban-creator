# 小红书内容图设计规范

## 三阶段目标

| 图片类型 | 在组图中的位置 | 优化目标 | 内容策略 |
|----------|--------------|----------|----------|
| **封面** | 第1张 | 点击率 | 见 cover.md |
| **内容页** `[content]` | image_01 ~ image_0{N-2} | 完读率 | 每页 2-4 个结构化信息点 |
| **尾页** `[tail]` | image_0{N-1} | 互动率 | 隐晦关注引导 + 氛围收束 |

---

## 内容页设计规范

**内容密度**：
- 文字占比：20-35%
- 每页字数：≤60 字
- 每页信息点：2-3 个，每点 ≤15 字
- 留白：35-45%

**6 种布局模式**（按内容类型选）：
1. **编号清单** — 步骤、要素列举
2. **对比双栏** — Before/After，优劣对比
3. **步骤流程** — 有先后顺序的操作
4. **标注图解** — 图片+手绘说明
5. **数据卡片** — 数字/数据展示
6. **Q&A 对话** — 问答式知识

**视觉规范**：
- 字体：圆角/手写，避免黑体/等线
- 高亮方式：色块或荧光线标记，勿加粗
- 背景：真实照片场景（每张不同场景）
- 批注：手绘风格，与封面保持一致
- 色调：与封面统一

**视觉多样性**（3 张以上内容图时）：
- 3+ 种不同实景背景
- 构图角度变化（正视/俯视/局部特写）
- 焦点位置错落（左/中/右交替）
- 批注样式轮换（不完全重复同一种）

**禁止**：
- 3D 渲染/纯色大背景
- PPT 式对称布局
- 科学海报风格
- 无结构文字墙
- 连续 3 张相同视觉元素
- 手机框/设备框

---

## 尾页设计规范

**内容**：
- 2-3 条前瞻性内容提示（预告"还有更多"，每条 20-40 字）
- 一句氛围收束语（营造"这只是开始"的感觉，不说"关注我"）
- 互动钩子（引导评论互动，自然带出"下期见"之类的语气）

**隐晦引导原则**（绝不直接求关注）：
- 通过内容价值暗示："这只是冰山一角"、"收藏夹里还有很多"
- 通过语气暗示："下期讲XX"、"持续更新中"
- 通过互动暗示："想看XX的评论区告诉我"（用户互动后会自然收到推送）
- 禁止："关注我"、"点关注"、"去主页"等硬性引导

**视觉**：
- 与内容页保持风格一致但适度克制（不过度花哨）
- 信息相对宽松（比内容页留白更多，营造"未完待续"的呼吸感）

## 图片内容规划（image-plan.md）

基于选题方向、最终标题和目标受众，在生成图片前先独立规划每张图的具体内容，写入 `$DIR/image-plan.md`。

**图片总数**：N 张（奇数，3-7 张），N 即后续 `--count` 基数（内容图 = N-1 张，封面单独生成）。

**格式模板**：

```markdown
# 图片内容规划

## 总体策略

- 主题方向: xxx
- 目标受众: xxx
- 图片内容定位: xxx
- 计划图片数量: N 张

---

## cover 封面

- 钩子: （≤10字）
- 辅助信息: （≤15字）

---

## image_01 [内容] 主题：xxx

- 信息点1: （8-15字）
- 信息点2: （8-15字）
- 推荐布局: 编号清单 / 对比双栏 / 步骤流程 / 标注图解

---

## image_0{N-1} [尾部]

- 引导点1: （隐含关注动机的内容，20-40字）
- 引导点2:
- 氛围收束句: （不直接说"关注"，而是营造"想看更多"的感觉）
```

## Prompt 模板

**内容页**：
```
{page_content}

页面类型：内容图（{page_type}），小红书信息流内容
风格延续：{style_description}（与封面保持一致）

平台规范：
- 3:4 竖版构图
- 真实照片背景（与其他内容图不同场景）
- 2-3 个结构化信息点，每点≤15字
- 圆角/手写字体，荧光色块高亮核心词
- 手绘批注风格
- 文字占比 20-35%，留白 35-45%
- 禁止：纯色背景、PPT布局、3D渲染、设备框

内容主题：{user_topic}
全文概要：{full_outline}
```

**CLI 命令（批量，必须使用 --count）**：
```bash
anbanwriter image generate "{paged_prompt}" --mode xhs --count N-1 --ref ./cover.png -o ./
# 输出自动命名为 image_01.png, image_02.png ... image_0{N-1}.png
```

> **关键规则**：内容图必须用 `--count` 批量生成，严禁逐张调用，否则视觉一致性无法保证。
