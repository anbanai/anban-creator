# 新人资料入口：第一批体验改进

日期：2026-10-09。评审分支：`feature/project-creator-onboarding`，基于 `001bfa1`。

## 本批交付

项目创建后的资料引导，默认先让用户用一段话介绍业务、读者和创作想法。原来的四步详细填写入口继续保留，两种方式切换不丢已填信息。已有项目定位会预填，避免重复介绍。

分析结果默认展示可阅读的资料卡。用户可直接改文字；嵌套字段、数组、数值、布尔值和空值保留原结构。来源标签、待补充项、依据和分析局限单独呈现。原 JSON 编辑保留为高级入口，用于增删字段、调整列表结构或修改非文本值。

首次资料仍须用户主动确认。确认后可直接进入原有任务创建窗口，并带入项目及原入口指定的任务类型，不自动生成或发布作品。

同时修复编辑保护：后台刷新不覆盖未保存文字，保存一项不丢失另一项修改，旧版本响应不回退新版本；版本冲突保留输入并阻止覆盖提交。关闭弹窗需要确认丢弃，浏览器刷新/离开有未保存提醒。弹窗底栏不再造成外层滚动和标题裁切。

## 数据和执行边界

- 无服务端、数据库、API、发布、计费、Skill 或 Agent Pack 改动。
- 简述复用 `ProfileAnalysisAnswers.intent.direction`；其他详细答案照常提交。仅用户点击“整理我的创作资料”才调用现有分析接口。
- 六维资料继续使用原 `ProjectProfile`，保存携带当前版本号，确认与历史修订仍由服务端负责。
- 不重新解释来源标签，不将 AI 推断自动标为事实。已确认资料重新分析后自动应用是原有服务端行为，本批只明确提示这一点。
- 这不是完整的对话式 Project Creator，也不包含多轮追问、业务草稿持久化、跨设备恢复或首稿生成质量验证。未提交文字只存在当前页面，关闭提醒不等于已经保存。
- 保留原新建/编辑项目字段、详细画像引导、单维度保存、确认、重试、更新和任务返回路径。`profile/*.md` 文件名对照表从日常资料展示中移除；对应数据及文件协议不变。

## 评审与验收

1. 新建项目后，检查简述预填、空白禁止提交、详细入口，以及两种填写方式切换后的保留行为。
2. 首次分析完成后，直接修改资料卡文本，再确认；确认前不得把草稿当作已确认资料。
3. 同时编辑定位、风格，只保存定位，风格文字必须保留。模拟后台刷新和版本冲突，不得静默覆盖本地修改。
4. 关闭有修改的弹窗，选择继续编辑/放弃；浏览器刷新触发未保存提示。
5. 确认并保存资料后进入创作，验证项目 ID 与原任务类型继续携带。

代码验证：`cd studio && bun run test -- --maxWorkers=2`、`bun run build`。新增测试覆盖简述与详细信息衔接、结构保真、空资料连续输入、确认边界、保存多项、后台刷新、版本冲突、关闭保护和任务入口。

验证结果：完整前端测试 124 个文件、1089 项通过；生产构建通过。仅有既有 Vite 配置迁移提示和大分包警告，不影响构建结果。

另修复原 `nginx-proxy-config.test.ts` 的 Windows 换行兼容性：读取 YAML 后统一 CRLF/LF，原代理与端口断言全部保留，不修改部署配置。

本机浏览器使用实际业务组件和隔离的演示 API，走通简述 → 修改资料 → 确认 → 创作入口。演示不调用真实 AI，不连接生产，不证明分析质量或真实生成/发布成功。临时预览位于 Git 忽略目录 `studio/tmp/`，不进入生产构建。
