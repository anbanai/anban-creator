# 分支、审核与发布

团队约定（2026-10-26）：

1. 每次修改先获取最新 `main`，从它建立各自的 `feature/*` 分支；多文件修改使用独立 worktree，保留其他人的未提交内容。
2. 功能开发、验证后推送功能分支。测试环境就绪后，协调好测试窗口，再将待测版本同步到共享 `dev` 分支并部署测试环境。覆盖 `dev` 前必须确认没有其他合伙人正在测试，避免覆盖彼此的版本。
3. 测试通过后，由功能分支向 `main` 发起 Pull Request；审核确认后才合并，再使用生产流水线发布。不要从可能混有其他未完成工作的共享 `dev` 直接合并生产。
4. 如果 `main` 在审核期间有更新，应在功能分支同步并重新验证。需要覆盖共享 `dev` 时先保留其原提交，使用带租约保护的更新，保留回退依据。

当前测试环境尚未搭好：本地验证后只提交 PR，等待审核；不覆盖 `dev`，不自动合并，不执行生产发布。本地测试通过不等同于测试环境或生产验收通过。
