# 统一选题库版本切换

选题统一使用 `ContentAsset.asset_id`。`TopicPool` 只记录人设归属、领取和历史使用，队列行 ID 不再是创作入口的选题身份。

## 用户路径

- `/topics`：单列选题列表；搜索、人设、使用状态、页码和抽屉定位保存在 URL。
- 人设、首页、热点保存、作品来源和内容分析统一进入 `/topics`；热点雷达保留。
- 选题 → 选择人设 → 现有创作表单，携带 `asset_id`；作品和复用继续使用现有任务、结果及内容链路。
- 自动找题与手动“找新选题”共用调度入口；定时找题、自动脚本分别设置。
- “某人设已使用”“脚本完成”“发布成功”“真实表现”分别表达，不相互替代。

## 服务端合同

| 能力 | 合同 |
| --- | --- |
| 列表、详情、人工添加 | 现有 `/content-assets` API，使用 `asset_id`；列表批量返回人设使用情况和作品、脚本摘要。 |
| 任务创建 | 传入 `asset_id`；校验归属、冻结创作输入，领取与任务、计费准入在同一事务完成。 |
| Agent 领取 | `claim_topic(project_id, task_id)`；任务必须已存在，重复领取与重试沿用原题。 |
| 脚本 | `POST /content-assets/:id/scripts`，传 `project_id` 与目标参数；持久化 job 和冻结输入，失败可按 job ID 恢复，不占用文章资格。 |
| 自主调研 | 单个 topic-radar Agent；初始人设、策略冻结；新增引用需匹配本次执行成功的搜索/抓取凭证，Server 验证、排序、入库。 |
| 来源与结果 | 使用 canonical asset ID 保持任务、研究、脚本、复用和分析关联；合并资产保留历史使用记录与冻结快照。 |

选题生成和搜索接入现有计费链路。余额不足或任务落库失败不占题；已创建任务失败后保留关联。再次创作使用复用流程。

## 发布顺序与数据

Server、Studio 和 Harness 必须作为同一次版本切换交付。Harness 原生 Claude/Codex 清单同步为 `4.2.134`，topic-radar Pack 为 `1.0.1`。旧选题页面和旧 HTTP 队列入口已删除，不提供长期兼容跳转或双写。

启动时先执行模型结构迁移，再运行 `MigrateTopicPoolToContentAssets` 及历史关联回填。回填可重复运行，保留旧队列 ID、领取时间、任务和脚本 ID、冻结输入、产物和发布历史；不清空现有内容。发布前按项目既有流程备份数据库，安排同版本切换。

通知链接使用既有 `server.public_base_url` 公网 HTTPS 根地址，定位 `/topics?project_id=...&asset_id=...`。未配置公网地址时保留通知正文并省略链接。运行环境仍需配置 topic-radar Agent 镜像、搜索能力及现有通知渠道。

## 实现取舍

- 队列和任务中的历史选题文字作为冻结快照保留，可编辑正文只在 ContentAsset 上维护。
- MCP 领取绑定已存在的任务，以保证重复调用和任务重试沿用原题；独立调研只新增候选。
- 复用沿用已有流程；研究和参考来源只建立关联，实际内容生产才记录人设使用。
- 保留现有资产和研究服务 API 名称；移除旧页面入口、重复客户端及独立队列编辑能力。
