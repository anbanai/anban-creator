# Agent Progress Hooks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove Anban-specific progress MCP calls from the managed Claude Agent workflow by deriving structured progress from official Task metadata, Agent Pack declarations, Runner Hooks, and artifact validation.

**Architecture:** Agent Packs declare ordered stages, percentages, and required artifacts. Claude Agent SDK `PostToolUse` observes `TaskCreate|TaskUpdate`, `Stop` validates delivery, and a Runner-local emitter sends structured events through the existing authenticated progress endpoint. The server resolves stages against the execution's frozen Agent Pack snapshot. Codex keeps its existing explicit progress calls until an official host-level Task event adapter exists, because the repository documents that Codex plugins do not support bundled Hooks.

**Tech Stack:** Go 1.x, YAML Agent Pack catalog generation, TypeScript/Bun, Claude Agent SDK 0.3.220 Hooks, Fiber handlers, GORM repositories, Redis progress SSE, table-driven Go tests, Bun tests.

---

## File Map

The implementation should keep responsibilities separated:

- `server/agentpack/types.go`, `server/agentpack/catalog.go`: declarative progress schema and validation.
- `plugins/packs/*/agent-pack.yaml`: stage and artifact declarations; generated native Agent sources remain derived outputs.
- `server/agentpack/catalog_test.go`: schema and catalog contract tests.
- `agent-ts/src/progress.ts`: host-neutral progress event types, pack lookup, dedupe, and monotonic emission.
- `agent-ts/src/artifact-validator.ts`: task-local required-artifact validation with path safety and non-empty checks.
- `agent-ts/src/reporter.ts`: structured progress transport over the existing agent endpoint.
- `agent-ts/src/bootstrap.ts`: typed catalog progress fields and validation of the frozen pack identity.
- `agent-ts/src/runner.ts`: Claude SDK Hook registration and event translation.
- `agent-ts/test/progress.test.ts`, `agent-ts/test/artifact-validator.test.ts`, `agent-ts/test/runner.test.ts`: Runner unit and Hook contract tests.
- `server/handler/agent.go`, `server/service/task_agent.go`: structured agent progress request handling and execution-pack validation.
- `server/service/task_progress_stages.go`: deleted after all callers use Agent Pack stage metadata.
- `server/handler/agent_test.go`, `server/service/task_execution_pack_test.go`: server contract and frozen-pack tests.
- `plugins/packs/moments/agent.claude.md`: pilot Agent migration to Task metadata.
- `plugins/packs/article/agent.claude.md`, `seednote/agent.claude.md`, `ecommerce/agent.claude.md`, `live-slicer/agent.claude.md`, `montage/agent.claude.md`: remaining Claude source migrations.

- `plugins/.claude-plugin/plugin.json`, `plugins/.codex-plugin/plugin.json`: same patch version bump after plugin assets change.
- `plugins/CODEX.md`: document the Codex compatibility gate; do not claim Codex migration complete without an official Task event adapter.

export interface StageProgressEvent {

    title: event.title,

## Completion Criteria

- Managed Claude Agent sources never call `update_task_progress`.
- Stage progress comes from official Task metadata observed by Claude SDK Hooks.
- Agent Pack metadata is the only percentage/title/artifact declaration source.
- Missing stage artifacts prevent completion progress and final 100 percent.
- Server progress remains authenticated, monotonic, persisted, and SSE-visible.
- `/btw` is not used for telemetry.
- Codex limitations are explicit; no unsupported hook or polling mechanism is introduced.
- Full Go, Agent Runtime, build, and Agent Pack checks pass.
