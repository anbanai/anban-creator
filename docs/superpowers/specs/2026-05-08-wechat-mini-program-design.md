# Anban Creator WeChat Mini Program Design

## Context

Anban Creator Studio 是一个基于 React 的 Web 前端，提供内容创作管理功能。用户需要移动端访问能力，尤其是微信小程序，以便随时随地管理账号、创建任务、查看进度。后端 API 已完整（含 `wx-login` 微信登录端点），只需新建 uni-app 小程序前端。

**目标：** 用 uni-app 构建微信小程序，移植所有面向普通用户的业务功能，排除桌面/开发者专属功能。

---

## 技术栈

- **框架：** uni-app + Vue 3 Composition API + TypeScript
- **状态管理：** Pinia
- **构建工具：** Vite（uni-app 内置）
- **UI：** 自定义组件库 + SCSS 变量主题
- **图表：** uCharts（轻量 Canvas 图表）
- **富文本：** mp-html（小程序富文本渲染）

# Part I: Visual Identity & Design System

## 设计方向

**"Editorial Warmth meets Intelligent Precision"**

内容创作工具应该让用户感到从容、专业、被赋能。不是冷冰冰的 SaaS 仪表盘，也不是花哨的消费级 app。

- **专业但温暖** — 像一位经验丰富的编辑助手
- **智能感** — 通过精致的微交互传递 AI 能力
- **呼吸感** — 信息不过载，留白充足，内容创作者需要思考空间
- **中国设计语境** — 符合微信生态审美习惯，不照搬西方 SaaS

# Part III: Interaction Patterns

## 全局交互规范

### 导航

| 模式 | 规范 |
|------|------|
| 进入子页面 | `uni.navigateTo`（保留 Tab 栈） |
| 返回上一页 | 系统返回键 / Navigation 左侧返回箭头 |
| 切换 Tab | 底部 Tab Bar |
| Tab 页内返回 | 不允许 navigateBack 到其他 Tab（系统行为） |
| 深度链接 | 支持 `?channel_id=xxx` 等参数直接跳转子页面 |

### 加载状态

| 场景 | 表现 |
|------|------|
| 首次加载 | 骨架屏（灰色块模拟内容形状） |
| 下拉刷新 | 系统下拉刷新动画 |
| 触底加载 | 底部 loading spinner |
| 按钮提交 | 按钮 loading + 禁用 |
| 页面切换 | 无额外 loading（系统转场动画） |

### 空状态

所有列表页面统一空状态：
- 插图（128rpx × 128rpx）
- 标题文字（"还没有 XXX"）
- 描述文字（可选）
- 操作按钮（可选，primary 色）

### 错误处理

| 场景 | 表现 |
|------|------|
| 网络错误 | 页面顶部黄色警告条 + 重试按钮 |
| API 错误 | Toast 显示错误消息（2s） |
| 表单校验 | 字段下方红色提示文字 |
| 401 过期 | 自动刷新 token，对用户透明 |
| 刷新失败 | 退出登录 → 重新静默微信登录 |

### 弹窗/对话框

| 类型 | 用途 | 样式 |
|------|------|------|
| `uni.showModal` | 确认操作（删除、归档、取消） | 系统原生样式 |
| 底部 Popup | 表单（反馈、充值）、筛选条件 | 圆角顶部 + 遮罩 |
| Toast | 操作成功/失败提示 | 系统原生 Toast |

### 手势交互

| 手势 | 场景 |
|------|------|
| 下拉 | 刷新列表 |
| 左滑 | 显示操作按钮（归档/删除） |
| 点击图片 | 全屏预览 |
| 长按 | 复制文字（邀请码等） |

## 认证流程

### 微信登录（静默）

服务端已实现 `POST /api/v1/auth/wx-login`（`server/handler/auth.go:545-629`），接受 `{ code, nickname?, avatar? }` 返回 JWT。

**App.vue onLaunch 流程：**

1. `uni.getStorageSync('anban_creator_token')` 检查缓存 token
2. Token 有效 → 调用 `GET /api/v1/auth/me` 刷新用户数据
3. Token 无效或不存在 → `uni.login()` 获取 code → `POST /api/v1/auth/wx-login` → 存储 JWT
4. 失败 → 显示错误 + 重试按钮

### Token 刷新

复用 Studio 的队列式刷新模式（`studio/src/lib/http-client.ts:38-97`）：

- 401 响应时检查是否已有刷新进行中
- 有：排队等待新 token
- 无：`POST /api/v1/auth/refresh` → 更新存储 → 重放排队请求
- 刷新失败：清除存储 → 重新静默登录

### 存储 Key

- `anban_creator_token`
- `anban_creator_refresh_token`
- `anban_creator_user`

## API 层

### HTTP 客户端（`api/index.ts`）

基于 `uni.request` 封装，非 axios：

- 自动注入 `Authorization: Bearer <token>`
- 响应解包：`{ code, msg, data }` → 返回 `data`
- 401 自动刷新 + 重试
- 统一错误提示
