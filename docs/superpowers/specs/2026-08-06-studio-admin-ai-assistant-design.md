# Studio AI助手管理员权限设计

## 目标

将 Studio 的 AI助手调整为管理员专用能力。普通用户既看不到入口，也不能通过直接访问根路由绕过权限，同时保留管理员现有的 `/` 访问地址。

## 导航

普通用户导航按以下顺序显示：

1. 项目
2. 任务
3. 计划
4. 钱包

管理员导航在上述 MVP 入口之后通过现有无标题分隔线展示，顺序为：

1. AI助手
2. 设计师
3. 模板库
4. Claude Code
5. Codex
6. 设置

`AI助手` 从 `mvpNavItems` 移入 `adminNavItems`，保留 `/`、`Sparkles` 图标和精确匹配行为。`allNavItems` 继续由 MVP 与管理员集合组成，侧边栏和命令面板因此使用同一权限来源。

## 路由与回退

根路由 `/` 继续渲染 `DashboardPage`，但外层增加 `AdminRoute`。管理员访问 `/` 时行为不变。

普通用户出现以下情况时统一跳转 `/projects`：

- 登录或注册成功后由现有页面默认导航到 `/`；
- 直接访问 `/`；
- 访问设计师、模板库、接入指南或设置等其他管理员路由。

`AdminRoute` 的默认回退地址从 `/` 改为 `/projects`，由根路由守卫同步完成登录后的角色分流，避免根路由也受保护后产生重定向循环。登录和注册表单不需要新增角色判断。缺少完整 `is_admin` 字段时继续保持等待，不提前错误重定向。

## 测试与验收

- 导航测试断言普通用户集合为“项目、任务、计划、钱包”，管理员集合以“AI助手”开头且全部标记 `adminOnly`。
- 侧边栏测试断言普通用户看不到 AI助手，管理员仍可看到且位于无标题分隔区。
- `AdminRoute` 测试断言普通用户回退 `/projects`，管理员可访问受保护内容，权限字段未就绪时不错误跳转。
- App 路由契约测试断言 `/` 的 `DashboardPage` 使用 `AdminRoute` 保护。
- 运行完整 Studio 测试与生产构建。
- 在普通用户与管理员会话下验证桌面和移动导航、根路由回退、无溢出、无重叠和控制台健康。

## 非目标

- 不删除 `DashboardPage` 或修改 AI助手业务逻辑。
- 不更改管理员权限数据模型或 Server API。
- 不改变项目、任务、计划和钱包页面行为。
