# 小红书图片内容规划步骤设计文档

**日期**：2026-03-17
**状态**：待实现
**影响文件**：`agents/rednote.md`

---

## 问题描述

小红书创作流程中，图片生成直接依赖文案正文（`content.md`）作为内容来源。由于小红书文案设计上就是简洁对话式的（三段式：开头钩子 + 2-3 段正文 + CTA），导致：

1. **情感/体验类笔记**：文案是情绪化种草，图片却无实质内容可展示
2. **知识/干货类笔记**：文案写得简洁，图片内容也跟着稀薄，无法达到"每页 2-4 个结构化信息点"的标准

根本原因：文案（供阅读，简洁对话式）和图片内容（供视觉呈现，高密度结构化）服务不同目的，却共用同一份内容来源。

---

## 解决方案

在步骤 4（创作内容）和步骤 5（生成图片）之间，插入**步骤 4.5：图片内容规划**。

Agent 基于主题、标题、目标受众**独立规划**每张图的具体内容，写入 `$DIR/image-plan.md`。图片生成时 `image-plan.md` 替代文案正文，作为 `{full_outline}` 和各页 `{page_content}` 的内容来源。

**不在本方案范围内**：封面（cover）生成逻辑不变，image-plan.md 中的封面规划仅供生成统一 prompt 时参考，不修改现有封面生成流程。

---

## 流程变更

### 原创模式（原流程）

```
步骤4 创作内容(content.md)
  ↓
步骤5 生成图片
  封面：基于主题+文案生成
  内容图：--count 批量，{full_outline} = content.md 正文
```

### 原创模式（新流程）

```
步骤4 创作内容(content.md)
  ↓
步骤4.5 图片内容规划 → $DIR/image-plan.md
  输入：主题 + 标题 + 目标受众 + content.md（参考语气）
  输出：每页具体知识内容（主题+2-4信息点+布局）+ 确定图片总数 N
  ↓
步骤5 生成图片
  封面：流程不变（{page_content} = 封面钩子，来自 image-plan.md 封面规划）
  内容图：--count 批量，统一 prompt 由 image-plan.md 全部页规划合并构建
```

### 复刻模式（新增步骤 5.5）

```
步骤5 按改写模式生成内容(content.md)
  ↓
步骤5.5 图片内容规划 → $DIR/image-plan.md
  style-only（默认）：基于主题+目标受众独立规划，不复用源笔记具体内容
  medium：参考源笔记的信息结构，内容重新设计
  tight：参照源笔记页数和主题结构，替换具体措辞和细节
  ↓
步骤6 生成图片（同原创模式步骤5）
```

## image-plan.md 规范

### 文件结构

```markdown
# 图片内容规划

## 总体策略
- 主题方向: xxx
- 目标受众: xxx
- 图片内容定位: xxx（如：从情感种草扩展到实用干货，增加收藏价值）
- 计划图片数量: N 张（奇数，推荐5-7张；此数值即后续 --count 参数）

---

## cover 封面
- 钩子: （≤10字，吸引点击的一句话）
- 辅助信息: （1个数字或悬念，≤15字）

---

## image_02 [内容] 主题：xxx
- 信息点1: （具体内容，20-60字，含数字/场景/细节）
- 信息点2: （具体内容）
- 信息点3: （具体内容）
- 推荐布局: 编号清单 / 对比双栏 / 步骤流程 / 标注图解

---

## image_03 [内容] 主题：xxx
（同上结构）

---

## image_0N [尾部]
- 总结条目1: （核心 takeaway，20-40字）
- 总结条目2:
- 总结条目3:
- 一句话核心观点: （全文最重要的结论）
```

### 图片数量规则与文件命名

`image-plan.md` 中"计划图片数量: N 张"决定后续 `--count` 参数，agent 不得在步骤5中独立计算图片数量，必须以 image-plan.md 为准。

**文件命名约定**：
- 封面单独生成，输出为 `$DIR/cover.png`
- 内容图使用 `--count N-1` 批量生成，输出文件自动命名为 `image_01.png` ... `image_0{N-1}.png`（存入 `$DIR/`）
- 合计：`cover.png` + `image_01.png` ... `image_0{N-1}.png` = N 张

> 注：现有 `agents/rednote.md` 中检查文件时写的是 `image_02.png` 起始，需在修改步骤5时同步更正为 `image_01.png` 起始。

### 信息点丰富度标准

每个信息点必须是**可以直接放进图片的完整内容**，而非概念标题。字数 **20-60字**，包含具体数字、场景或可操作细节。

| 质量等级 | 示例 |
|---------|------|
| ❌ 差（概念词） | "介绍咖啡馆选择技巧" |
| ✅ 好（具体内容） | "🔍 看评分：大众点评≥4.5，且近30天有评价（排除刷分店）" |
| ❌ 差（泛化描述） | "附近有很多选择" |
| ✅ 好（含数据） | "深圳福田区：人均50-80的精品咖啡馆超过200家，值得打卡的不到30家" |
| ❌ 差（模糊步骤） | "第一步做准备" |
| ✅ 好（可执行步骤） | "Step1 出发前：查小红书「城市名+咖啡」，按收藏量排序，筛出收藏>500的" |

### 规划原则

- **情感/体验类主题须知识化扩展**：将情感体验转化为可复用干货（打卡体验 → 选址技巧；旅行感受 → 行程攻略）。适用于所有账号类型；如账号定位为纯情感/美学类（account info 中无干货/教程标签），可酌情减少知识化程度，但每页仍需至少 2 个有具体细节的信息点
- **每张图主题不重叠**：内容图之间信息点不交叉
- **信息点独立于文案**：不依赖文案正文的叙述，基于主题和目标受众独立推导

## 图片生成 Prompt 构建方式

`image-plan.md` 的内容通过以下方式传给 visual-design skill：

### 1. 封面（cover）

`{page_content}` = image-plan.md 中 `## cover 封面` 的钩子与辅助信息拼接为一句话，格式为：`{钩子} | {辅助信息}`。

示例：image-plan.md 中写 `钩子: 宝藏咖啡馆，你找到了吗？` / `辅助信息: 深圳隐藏20年的老街小店`，则 `{page_content}` = `"宝藏咖啡馆，你找到了吗？ | 深圳隐藏20年的老街小店"`。

封面生成命令和流程本身不变（`{full_outline}` 在封面生成中如当前一样使用 content.md 内容，此处不替换）。

### 2. 内容图批量生成（--count）

将 image-plan.md 中所有内容页（image_02 至 image_0N-1）和尾部页（image_0N）合并，构建一个统一的分页描述 prompt：

```
生成 {N-1} 张小红书内容图，按以下分页规划（请严格按序生成）：

第1张 [内容] 主题：xxx
- 信息点1: xxx
- 信息点2: xxx
- 推荐布局: xxx

第2张 [内容] 主题：xxx
...

第{N-1}张 [尾部]
- 总结条目: xxx
- 核心观点: xxx
```

此合并 prompt 作为位置参数（`{unified_content_description}`）直接传入命令行，`{full_outline}` 嵌入在 prompt 字符串内部（visual-design skill 内部处理，不是独立 CLI 参数）：
```bash
anbanwriter image generate "{unified_content_description}" \
  --count {N-1} \
  --mode xhs -o $DIR/
```

其中 `{unified_content_description}` 是包含所有分页规划的完整 prompt 字符串（含 `{full_outline}` 内嵌内容），由 agent 在调用前自行拼接构建。

## 修改范围

### `agents/rednote.md`

**原创模式**，在步骤 4 和步骤 5 之间插入步骤 4.5：

> **步骤 4.5 — 图片内容规划**：基于选题方向、最终标题和目标受众，独立规划每张图的具体内容。规划时不依赖文案正文的叙述，围绕主题自主展开知识内容。每个信息点 20-60 字，包含具体数字/场景/可操作细节。情感/体验类主题须知识化扩展（将体验转化为干货）。确定图片总数 N（奇数，5-7 张），此数值后续作为 `--count` 参数。结果保存到 `$DIR/image-plan.md`。

步骤 5 更新：
- 封面 `{page_content}` 使用 image-plan.md 封面规划内容
- 内容图批量 prompt 由 image-plan.md 各页规划合并构建（见"图片生成 Prompt 构建方式"）
- `--count` 使用 image-plan.md 中规定的 N-1（封面单独生成）

**复刻模式**，在步骤 5 和步骤 6 之间插入步骤 5.5，内容同原创模式步骤 4.5，区别：
- `style-only`：独立规划，不复用源笔记具体内容（可参考其页数作为参考上限）
- `medium`：参考源笔记信息结构，内容重新设计
- `tight`：参照源笔记的视觉结构（页数 + 各页主题，来自 `source-analysis.md` 新增的第6维度），替换具体措辞和数据

**对复刻模式步骤 3 的附加修改**：`source-analysis.md` 的 5 维模板提取新增第 6 维：
> **视觉结构模板**：图片总张数（含封面）、各内容页主题关键词（按顺序）

此数据用于 `tight` 模式图片规划时参照源笔记结构。若源笔记图片信息无法从 API 返回数据中提取，`tight` 模式的图片规划退回至 `medium` 模式行为（记录退回原因到 `source-analysis.md`）。

**文件组织**，在已有文件列表中补充：
```
- 图片规划：$DIR/image-plan.md（步骤4.5/5.5产物）
```

## 成功标准

1. 生成的内容图每页包含 2-4 个具体、可操作的信息点（含数字/场景/细节）
2. 情感/体验类笔记的图片能展示相关知识干货，不再仅是情绪描述
3. `$DIR/image-plan.md` 作为独立产物存在，可供审查；信息点字数均达到 20-60 字标准
4. 后续 `--count` 参数值等于 image-plan.md 中"计划图片数量"减 1（封面单独计）
5. 复刻模式下，`tight` 模式的图片页数和主题结构与源笔记 `source-analysis.md` 中记录的结构一致
